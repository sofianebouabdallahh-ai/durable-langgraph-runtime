# Phase L3b plan — Agent Studio: your own model

**Goal:** in Nuria, a person adds the models they want:
- a local **Ollama** (found automatically);
- an **OpenAI** key;
- an **Azure AI Foundry** deployment;
- any **OpenAI-compatible** service.

They **test** each one, pick a **default**, and choose a model **per agent and per helper** in the Studio. Keys are encrypted on the machine, never shown again and never logged. A conversation keeps the model it started with when the default changes.

**Part of:** the [local release](local-release.md) Studio slices (L3a agents & helpers ✅ → **L3b your own model** → L3c skills & "describe your agent" → **M2**).

**Requirements:**
- CR-006 **R18.2** (model connections);
- **R18.3** (keys are secrets, always);
- **R18.4** (choosing a model, with a capability check);
- the R17.2 form's **Model** row;
- the R17.3 rule that **publishing needs every chosen model to pass its test**;
- the R15.4 amendment (a turn records its model bindings);
- **AC44**, **AC45**;
- gap **G2** in its local form (the beta swaps the local master key for Key Vault: P8).

## 1. Research findings

| Topic | Finding | Consequence |
|---|---|---|
| How a run picks a model today | One provider per process, from `.env` (`MODEL_PROVIDER`, `MODEL_CHAT`…). Agent files name a *role* (`model: chat`); `OpenAICompatibleProvider` serves OpenAI and Ollama, and Foundry through its `/openai/v1/` route | The adapter stays. What changes is **which connection and model a role or a name resolves to**, per run, instead of per process |
| `provider:model` in definitions | The schema already accepts an explicit `name:model-id`, but at runtime it falls through to the default model | It gets a meaning: **`<connection>:<model>`**, e.g. `my-foundry:gpt-4o` or `ollama:qwen2.5:7b`. No schema change, and files and exports stay readable and portable (a missing connection is a plain validation issue) |
| Pinning | L3a pins the agent bundle; models referenced by role (`chat`) follow the workspace default, so changing the default mid-conversation would change the model of the next call *of a running turn* | At turn creation, resolve every model the bundle uses to a **binding** `{model string → connection id + model id}` and store it on the run (`runs.model_bindings`). The worker uses the bindings, not the current default |
| Encryption | No crypto library in the backend yet. **`cryptography`** (pyca) is the standard: AES-256-GCM (AEAD), maintained, wheels for every platform | Added under the existing uv cooldown. **Envelope encryption:** a random data key per connection (AES-256-GCM), wrapped by a **master key** (KEK). Locally the KEK is `NURIA_SECRET_KEY` in `.env`, generated by setup; the beta swaps it for Key Vault (same interface: Strategy) |
| Binding ciphertext to its place | AES-GCM's additional authenticated data (AAD) authenticates context without encrypting it | AAD = `workspace : connection id : purpose`. A ciphertext copied to another row or workspace **fails to decrypt** (AC45's second clause) |
| Capability check | Agents need tool calling; small local models often can't. A real call proves the URL, the key, the model and tool support at once | **Test** sends one tiny request with a `ping(value)` tool and expects a tool call. It reports *ready*, or why not (unreachable, 401, unknown model, no tool calls, too slow) in plain words |
| Discovering models | Ollama lists pulled models at `GET /api/tags`; OpenAI-compatible services at `GET /v1/models`; Foundry deployments are typed in | The add form suggests models where it can; the model name is always editable |
| Ollama detection | Setup already finds a native Ollama on the host (`host.docker.internal:11434`) | **Add a model → Ollama** probes the same addresses and pre-fills the URL and the models |
| Proving AC44 without keys (CI) | The phase-6 contract tests run the real adapter against a tiny fake OpenAI server | A small **fake OpenAI-compatible server** (`runtime fake-model`, dev tooling, a CI-only Compose profile). It answers deterministically and records which model and which key served each call. Two connections to it prove **different helpers use different connections in one conversation**, with no real key. The live proof uses the Ollama on this machine; Foundry live needs your key |
| SSRF | A base URL typed by a user is fetched by the server | Locally, one user on their own machine: allowed (Ollama is on the host). Recorded as a **beta gap**: the hosted beta needs an egress allow-list for connection URLs (P8) |

## 2. Design

```
 Settings → Models ─► POST /models/connections ─► seal(key) ─► model_connections (ciphertext)
                      POST …/test ─► worker-side adapter call (tool ping) ─► ready | why not
 Studio form: model per agent / helper ─► "<connection>:<model>" or a role ("chat" = default)
 send a message ─► pin bundle (L3a) + bind models {string → connection id, model id} ─► run
 worker ─► bindings ─► open(key) in memory ─► OpenAI-compatible adapter ─► the model
```

### 2.1 Data (migration 0011)
- **`model_connections`:**
  - `id`, `workspace_id`;
  - `name` (kebab id, used in definitions), `display_name`;
  - `kind` (`ollama | openai | azure_foundry | compatible`), `base_url`;
  - **`key_ciphertext`, `key_nonce`, `dek_ciphertext`, `dek_nonce`, `kek_version`**;
  - `key_fingerprint` (8 hex characters of a keyed hash: "the same key?" without the key);
  - `models` (suggested names), `test_status` (`untested | ready | failed`), `test_detail`, `tested_at`;
  - `created_at`, `updated_at`, `archived_at`.
- **`workspace_settings`:** the default connection and model.
- **`runs.model_bindings`:** jsonb.
- **Grants:** the API manages connections and settings; workers read them (they decrypt in memory, for the call only).

### 2.2 Backend
- **`keys.py`:**
  - `seal(plaintext, aad) → Sealed`, `open(sealed, aad)`;
  - a `KeyEncryptionKey` port with `LocalKek` (`NURIA_SECRET_KEY`); the beta adds `KeyVaultKek`.
  - **Patterns:** Strategy (the KEK), envelope encryption.
- **`ConnectionStore` + `ConnectionService`:**
  - add (the key is sealed before it touches the database), edit (keep the key unless a new one is typed), test, archive, set the default, list models, discover Ollama.
  - Plaintext keys live only in the request handler and in the worker's call.
- **`ModelRouter`** (worker and API):
  - `bind(definition) → bindings` at turn creation;
  - `chat_model(binding, temperature)` in the worker: an adapter per (connection, version, model, temperature), cached; the key is opened in memory;
  - the setup's `.env` model stays as the **setup connection** (read-only, shown in Settings), the fallback when nothing is configured;
  - the circuit breaker becomes **per connection**.
- **Validation:**
  - a model string naming a connection that doesn't exist or is archived is an issue at `model` / `helpers.<n>.model`;
  - **publish blockers** gain "Test the model *X* (Settings → Models)".
- **API (`/models`):** `GET/POST /models/connections`, `PATCH/DELETE …/{id}`, `POST …/{id}/test`, `GET …/{id}/models`, `GET /models/ollama`, `GET/PUT /models/default`. `GET /studio/catalog` adds the models people can pick.
- **AC45 hygiene:**
  - responses carry `has_key` and the fingerprint, never the key;
  - provider errors pass through `redact()`;
  - doctor bundles redact `NURIA_SECRET_KEY`;
  - a test **searches every response, event, transcript and container log for the key**.

### 2.3 UI
- **Settings → Models** (sidebar):
  - the default model picker at the top;
  - a card per connection (kind icon, name, URL, status: *Ready ✓*, *Not tested*, *Failed: reason*; its models);
  - Test, Edit, Remove;
  - the setup's model shown read-only.
- **Add a model:** choose the kind (4 tiles), then a form with help for each kind:
  - where to find the key;
  - Foundry's endpoint and deployment;
  - Ollama pre-filled from detection.

  **Save & test** in one step.
- **Studio → Model:** a picker per agent and per helper:
  - "Default (*the current default*)", then each ready connection's models;
  - a model whose connection isn't ready is marked, with a link to Settings.
- **Chat:** the reply header shows which model answered ("Nuria · qwen2.5:7b"); "What happened?" lists the model of each call.

## 4. Success criteria

| # | Criterion | How | Pass when |
|---|---|---|---|
| SC1 | **Add a model without a terminal** | Browser: Settings → Models → Ollama (detected) / OpenAI-compatible (URL + key + model) → Save & test | *Ready ✓*; the model appears in the Studio picker; **5/5** |
| SC2 | **AC44: different models in one conversation** | An agent on connection A with a helper on connection B (CI: two fake connections; live: Ollama + a second model or service) | One turn: the main agent's calls go to A, the helper's to B (the fake records them; "What happened?" shows them); **5/5** |
| SC3 | **AC45: the key appears nowhere** | A known key saved, used, tested, failed on purpose | Not in any API response, run event, transcript message, the doctor bundle or the containers' logs |
| SC4 | **Ciphertext is bound to its place** | Copy a connection's ciphertext to another connection or workspace; use the wrong master key | Decryption fails, every time |
| SC5 | **The test tells the truth** | The fake answering: correctly; 401; an unknown model; no tool call; never | Ready / "The key was refused" / "This model isn't available" / "This model can't use tools" / "Didn't answer in 30 s" |
| SC6 | **Pinned models** | Change the default while a turn is queued; then send again | The queued turn uses its bound model; the next turn uses the new default |
| SC7 | **Publish needs tested models** | An agent whose helper uses an untested or failing connection | Publishing is blocked with the model named; testing it unblocks |
| SC8 | **Keys survive restarts, not leaks** | Restart the stack; rotate a key (edit) | Chats keep working; the old key is gone (the fingerprint changes); nothing else re-entered |
| SC9 | **Durability unchanged** | Kill the worker mid-turn on a non-default connection | Completes on the same connection, no duplicates |
| SC10 | Quality | CI | Backend `make check`, UI check, browser suite 5× (with the fake), axe clean on Settings |
| SC11 | Docs | Follow the models guide on a clean stack | Works without unwritten steps |

## 5. Risks

| Risk | Mitigation |
|---|---|
| A lost `.env` loses the master key, so saved keys can't be opened | Said in the UI and the docs ("keep `.env` safe; without it, re-enter your keys"); a clear "can't open this key, re-enter it" state instead of a crash |
| A key leaks through an error message or a log | Errors pass through `redact()`; the key is opened only inside the adapter call; SC3 searches everything |
| Small local models can't call tools | The test says so in plain words before an agent depends on it; publishing is blocked |
| Provider differences (Foundry routes, auth headers) | One OpenAI-compatible adapter, with the Foundry `/openai/v1/` route already proven in phase 6c; kind-specific URL help in the form |

## 6. Out of scope
- Prices per model and cost estimates per preset (later; costs stay as configured today).
- Embedding models per connection.
- Several workspaces or roles, and Key Vault (hosted beta: P7, P8).
- An egress allow-list for connection URLs (beta gap, P8).
