# Design

How the runtime is built and why. Requirements (*what*) live in the [spec](requirements/Project_4_Detailed_Requirements_K8s.pdf) and [change requests](requirements/). Individual decisions are recorded as [ADRs](adr/). This document is the map that connects them, and it grows phase by phase.

## Pattern catalogue

Every non-trivial component names the pattern it applies. If no pattern fits, the code says so instead of forcing one.

| Pattern | Where | Why here |
|---|---|---|
| **State machine (table-driven)** | [`runs/state.py`](../backend/src/agent_runtime/runs/state.py) | Run lifecycle rules (R1.1) as data: one place answers "is this transition legal?" for the API, workers and reaper, and the whole table is unit-tested. Waiting states return through `queued`, so every resume takes a fresh lease. |
| **Repository** | [`runs/store.py`](../backend/src/agent_runtime/runs/store.py) `RunRepository` | Only this class knows the SQL for runs and events. Callers use domain operations and get immutable `Run` / `Event` objects back, never raw rows. |
| **Unit of Work** | Call sites: `async with conn.transaction()` | The repository is bound to a connection and doesn't decide transaction boundaries beyond a single atomic operation. Callers group operations that must succeed or fail together; nested calls become savepoints. The executor uses this to commit a status change, its events and the checkpoint as one unit. |
| **Optimistic concurrency (conditional update)** | `RunRepository.transition` | `UPDATE … WHERE status = ANY(legal sources)`. When two processes race, exactly one row update succeeds; the loser gets `InvalidTransition` with the real current status. No lock is held across the race. |
| **Transactional event log** | `RunRepository.append_event` | A status change and its event commit together (R1.1). Events are persisted *before* any publish (R1.5, phase 3), so the log is the source of truth and pub/sub is only a notification. |
| **Gap-free sequence via row lock** | `runs.last_event_seq` | `UPDATE … SET last_event_seq = last_event_seq + 1` serialises writers per run and gives the number back on rollback. That makes `seq` strictly increasing and gap-free, which the replay/dedup algorithm (R2.5) relies on. A Postgres `SEQUENCE` would leave gaps. |
| **Content-addressed snapshot** | `agent_definitions.hash` (migration 0002) | A run references the exact definition it started with, by hash. Identical definitions dedupe, and a changed file never alters an in-flight run (R15.4). |
| **Expand / contract migrations** | `backend/migrations/` | Schema changes are additive first (new columns are nullable or defaulted), so old and new code can run side by side during a rolling upgrade (R10.6, AC15). |
| **Fail-fast configuration** | [`config.py`](../backend/src/agent_runtime/config.py) | Invalid or missing settings stop the process at startup, with the field named, rather than failing later in the middle of a run. |
| **Fencing token** | [`checkpointing.py`](../backend/src/agent_runtime/checkpointing.py) `Fence`, `check_fence` (events, transcript and tool writes join in phase 2) | Every write carries the lease epoch, and the database rejects writes from a stale epoch, so a paused "zombie" worker can't corrupt a run it no longer owns (R2.3, R2.10). |
| **Protection Proxy** | `FencedCheckpointer` | Same interface as LangGraph's `AsyncPostgresSaver`; reads pass through, and every write runs inside our transaction after the fence check. It uses only LangGraph's public API, so an upgrade can't silently bypass the guard. |
| **Transactional Outbox** | [`runs/executor.py`](../backend/src/agent_runtime/runs/executor.py) `_Outbox` + `FencedCheckpointer.on_commit` | Node events are staged in memory while a superstep runs and committed **inside that superstep's checkpoint transaction**. A committed step always has its events; a step lost to a crash has none and is re-run. That gives exactly-once events per committed step. |
| **Observer** | `_NodeRecorder` (LangChain callback handler) | LangGraph notifies it inline when each node starts and ends, before the step's checkpoint (verified by experiment). It stages events and refuses to start a node once `max_steps` is spent. LangGraph's recursion limit can't enforce this, because it resets on every resume. |
| **Lease with heartbeat** | `RunRepository.acquire_lease` / `renew_lease`, `RunExecutor._under_lease` | Ownership is time-bound and renewed every `heartbeat_s`. A failed renewal means another worker took over, so execution stops. Fencing rejects anything it still tries to write (defence in depth). |
| **Service Layer** | [`runs/service.py`](../backend/src/agent_runtime/runs/service.py) | The use case "create a run" (graph exists, input valid, options within ceilings) is implemented once and shared by the API and CLI. Transport code only parses and renders. |
| **Registry** (graphs) | [`graphs/__init__.py`](../backend/src/agent_runtime/graphs/__init__.py) | Runs name a graph; the registry validates the name and input model, and builds an uncompiled graph that the executor compiles with the run's own fenced checkpointer. |
| **Registry** | [`agents/loader.py`](../backend/src/agent_runtime/agents/loader.py) `AgentRegistry` | The single lookup point for validated agent definitions. Nothing else reads agent files. |
| **Parse, don't validate** | [`agents/schema.py`](../backend/src/agent_runtime/agents/schema.py) | Frontmatter becomes strict, frozen pydantic objects at load time (`extra="forbid"`), so the rest of the code never handles raw YAML. Sub-agents get a *restricted* schema, so leaf-only rules hold by construction. |
| **Dependency inversion** | `Catalog` passed to `load_agents` | The loader validates against an injected catalogue of known tools, hooks, schemas and models instead of importing registries. Later phases add tools without touching the loader. |
| **Interface segregation** | [`config.py`](../backend/src/agent_runtime/config.py) `AgentSettings` ⊂ `Settings` | Commands that only read agent files depend on the small interface, so they need no database credentials (CI, laptops). |
| **Command** | [`cli.py`](../backend/src/agent_runtime/cli.py) | Each subcommand is a handler bound to its own parser; `main` only parses and dispatches. |
| **Ports & Adapters** | [`queue.py`](../backend/src/agent_runtime/queue.py) `WorkQueue` → `RedisWorkQueue`, `InMemoryWorkQueue` | Workers depend on an interface. One contract suite runs against both adapters, so the fast fake is proven to behave like Redis. |
| **Competing Consumers** | [`worker.py`](../backend/src/agent_runtime/worker.py) + Redis consumer group | Each new message goes to exactly one worker process; adding processes adds throughput. |
| **Bulkhead** | `Worker` (`--concurrency`) | At most C runs in flight per process. Reads and reclaims only ask for free slots, so a busy worker never hoards work. |
| **"Postgres decides, Redis delivers"** | Worker settle rules + lease | A message is a hint; the lease `UPDATE` is the only arbiter. Duplicates, stale messages and two recovery paths (reaper and relay) racing each other are harmless by construction (the F2 reclaim race). |
| **Outbox relay** | [`runs/relay.py`](../backend/src/agent_runtime/runs/relay.py) | `runs` is the outbox. A sweep re-sends a message for any run that needs one but whose message is gone (API crashed between INSERT and XADD, Redis flushed). Candidates are claimed with `FOR UPDATE SKIP LOCKED`, so concurrent sweeps never double-send. This is what makes Redis rebuildable. |
| **Heartbeat touch** | `RunExecutor` hook → `WorkQueue.touch` (`XCLAIM … JUSTID`) | Redis measures idle time from the last delivery, so a healthy long run would look dead. Touching the message on each heartbeat resets it; the reaper only takes dead workers' messages (verified by experiment, 1400 ms → 79 ms). |
| **Graceful hand-off** | `ReleaseRequested` → `RunExecutor._release` | On SIGTERM a run finishes its current step, then is released (`running → queued`, `run.released`) and re-sent. Another worker resumes it in ~0.01–0.05 s instead of waiting for the lease to expire. It isn't counted as a reclaim. |
| **Supervisor** | `runtime worker --workers N` | Starts N worker processes and forwards stop signals. It deliberately doesn't restart them: Kubernetes restarts pods, and demos need a killed worker to stay dead. |
| **Defence in depth (DB-enforced fencing)** | Migration `0004` trigger | The database rejects stale-epoch writes even if application code forgets the check or someone writes raw SQL. |
| **Least privilege** | Migration `0005` group roles + `runtime db provision-users` | One login user per component, holding only the grants it needs. Migrations hold no passwords. Tests prove the grants both **restrict** and **suffice**. |
| **Publish after commit** | `RunRepository.emitted` + `FencedCheckpointer.after_commit` + `publish_events` | An event is announced only after its transaction commits; a rolled-back (fenced) write is never seen by anyone. A failed publish is logged and never fails a run. Verified with a spy bus that checks visibility from another connection, plus a control test. |
| **Pub/Sub multiplexer** | [`streaming/broker.py`](../backend/src/agent_runtime/streaming/broker.py) | One Redis subscription per API replica, however many clients it streams to; channels are reference-counted. A single reader task resolves `SUBSCRIBE` confirmations, so opening a stream costs one round trip. |
| **Bounded queue + catch-up** | `Listener.overflowed` | A slow client never slows the broker or other clients: its queue overflows, it's flagged, and it catches up from Postgres. |
| **Functional core, imperative shell** | [`streaming/merger.py`](../backend/src/agent_runtime/streaming/merger.py) (core), [`streaming/session.py`](../backend/src/agent_runtime/streaming/session.py) (shell) | The replay/live/dedup/back-fill logic has no I/O, so it is verified with property-based tests (600 generated interleavings per run). |
| **Anti-entropy (safety-net poll)** | `RunStream` | Pub/Sub is at-most-once, so even the final event can be lost. If nothing live arrives for `stream_poll_s`, the stream reconciles with Postgres. |
| **Graceful drain** | `DrainingServer` + `app.state.draining` | SIGTERM flags the app before uvicorn shuts down: `/readyz` fails, new streams get `503`, and open streams send `event: reconnect` and close, so clients resume elsewhere with `Last-Event-ID`. |
| **Chain of Responsibility (fixed order)** | [`tools/pipeline.py`](../backend/src/agent_runtime/tools/pipeline.py) `ToolPipeline` | The only way a tool executes: resolve → schema → grant → `pre_tool` → re-validate → policy/approval → ledger (budget + idempotency) → execute → `post_tool` → truncate (R15.7). The order is fixed in code, not configurable, and a spy test pins it. Each stage can stop the call with a tool error the model can correct. |
| **Adapter** | [`tools/middleware.py`](../backend/src/agent_runtime/tools/middleware.py) `RuntimeMiddleware` | Adapts the LangChain-independent pipeline to `create_agent`'s `awrap_tool_call` / `awrap_model_call`. The runtime context (fence, grants, budgets) arrives through LangGraph's `context=`, never through globals. |
| **Registry + Decorator** (tools, hooks) | [`tools/spec.py`](../backend/src/agent_runtime/tools/spec.py), [`tools/hooks.py`](../backend/src/agent_runtime/tools/hooks.py) | `@registry.tool(...)` / `@registry.hook(...)` declare code with its risk class, caps and timeout. Agent files reference them by name only (R15.9); the same registries feed the definition validator's `Catalog`. |
| **Idempotency key + "record, then act"** | [`tools/invocations.py`](../backend/src/agent_runtime/tools/invocations.py) | Key = `sha256(run · node · call_index · tool · canonical args)`, without the epoch, so a retry finds it. `begin` records `in_progress` (and charges the budget) **before** the tool runs; `finish` stores the result. `done` → replay, never re-execute; `in_progress` from a dead owner → take over with the same key, which the tool uses to dedupe its own effect (R2.6). |
| **Fail closed** | `run_hooks` | A hook that raises or times out is a deny. A broken redaction hook withholds data; it never leaks it (R15.8). |
| **Durable pause (no lease held)** | `RunExecutor._pause`, `RunRepository.decide_approval` | `interrupt()` → `waiting_approval` with the payload; the lease is released and the message acked, so a pause can last for days with no worker involved. Approval is a database transition (`waiting_approval → queued` + `resume_value`) and a fresh message; any worker resumes with `Command(resume=…)`. |
| **Test double: scripted model** | [`models/scripted.py`](../backend/src/agent_runtime/models/scripted.py) | A real `BaseChatModel` replaying a script from the run input, chosen by turn number so it is replay-stable. Every test and e2e runs with no API key (R14.20). |
| **Atomic fan-in counter** | `RunRepository.transition` → `_child_ended` | A child's terminal transition increments its parent's `child_done` in the same transaction; the parent's row lock serialises siblings, so exactly one re-queues the parent (R2.8). `transition` is the single choke point for terminal transitions, so the worker, the reaper and an API cancel all count. |
| **Ports & Adapters** (spawning) | [`runs/fanout.py`](../backend/src/agent_runtime/runs/fanout.py) `Spawner` → `RunSpawner`, `LocalSpawner` | Workflow nodes ask for children and get results; whether those are durable runs on any worker or in-process tasks (`--local-fanout`) is the adapter's business. |
| **Enqueue after commit** | `RunRepository.ready` → `RunExecutor._send`, `RunService._enqueue` | A run that became queued (a spawned child, a fanned-in parent) is sent to Redis only after its transaction commits; the relay sweep repairs a lost send. The same rule as publishing after commit. |
| **Ordered locking** | Fan-out, fan-in, budget roll-up, cancel cascade | Every transaction that touches several runs of one tree locks them deepest first (child → parent → root), so sibling charges, fan-ins and cancels never deadlock. |
| **Admission control (backpressure)** | `RunService.create_run` → `Overloaded` → `429` + `Retry-After` | When the queue depth (counted in Postgres) reaches the limit, new runs are refused; workers' own fan-outs are not (R2.9). |
| **Supervisor (in-process)** | [`subagents/orchestrator.py`](../backend/src/agent_runtime/subagents/orchestrator.py) `SubagentOrchestrator` | Owns its sub-agents' lifecycle: spawn, track, limit (4 parallel, 10 total), time out, cancel, stop, recover. The main agent sees four tools; the sub-agent sees two (CR-005). |
| **One recovery path** | `stop()` / `recover()` | A pause, a graceful release and a crash all leave sub-agents `running` with a checkpoint; any (re)start resumes every running one from its own thread. Completed handles are never re-run (AC41). |
| **Shared fence, separate threads** | `FencedCheckpointer(fence = the main run's, thread = <run>/sub/<handle>)` | Sub-agents write under the main run's epoch, so a zombie's sub-agents are fenced along with it; each has its own checkpoint thread and outbox. They are stopped before the main run leaves `running`, because a pause keeps the epoch. |
| **Context isolation** | `asyncio.create_task(…, context=contextvars.Context())` | A graph started inside a running node otherwise inherits the parent's run: the parent's callbacks see its nodes (measured). Each sub-agent and local child starts in an empty context. |
| **Lock mode that never upgrades** | `check_fence` → `FOR NO KEY UPDATE` | The mode an `UPDATE` of non-key columns takes anyway: no share-to-exclusive upgrade, so two of a run's concurrent transactions can't deadlock; still conflicts with the takeover; doesn't block FK checks. |
| **Transcript as a projection** | [`sessions/transcript.py`](../backend/src/agent_runtime/sessions/transcript.py) `TranscriptWriter` | The chat transcript is derived from each checkpoint's messages **inside that checkpoint's transaction** (via the step outbox), so the agent's context and the user's view can't disagree (R12.4). Positional `sha256` ids make a re-produced superstep write nothing (AC19). |
| **Template Method** (streams) | [`streaming/session.py`](../backend/src/agent_runtime/streaming/session.py) `PersistedStream` → `RunStream`, `SessionStream` | One subscribe → replay → live → back-fill → poll algorithm; subclasses only say which channel and how to read a page. |
| **Durable lifecycle hooks** | `RuntimeMiddleware.abefore_agent`, `RunExecutor._session_end` | `session_start` runs in a checkpointed node with a flag in the thread's state (never twice, even across a reclaim); `session_end` is a run of its own kind (lease, fencing, reclaim); `turn_end` observes after commit. |
| **Stable identity for replay** | `user:<run_id>`, `repair:<run_id>:<call>` | A turn's position in its session thread is found from its user message's id on every execution, so nothing extra needs storing; tool calls a previous turn left unanswered are closed as this turn's own rows. |
| **Decorator** (model retries) | [`models/retry.py`](../backend/src/agent_runtime/models/retry.py) `ModelCaller` | Wraps one model call: retryable errors only, capped full-jitter backoff, `Retry-After`; the budget is charged before **every** attempt, so retries can't hide from it (R14.7). |
| **Circuit Breaker** | `CircuitBreaker` (one per provider per process) | 5 retryable failures in 30 s open it for 30 s; calls fail fast and the run is *released* for the relay to re-send later instead of burning retries; one trial call half-opens it. |
| **Soft limit → hard limit** | `RuntimeMiddleware.awrap_model_call`, `RunExecutor._complete(failed=…)` | At 80 % of any budget the main agent's next call has no tools and a note; any tool call it still returns is dropped. Its answer is stored marked `budget_limited` and the run ends `failed(budget:*)` (R14.2). |
| **Usage counted with the step** | `Outbox.add_usage` → `RunRepository.add_usage` | Tokens and cost commit with the checkpoint, so a run's totals are exactly the sum of its committed steps, across reclaims (AC26); rolled up to ancestors and the session. Model *calls* stay counted immediately: they are the runaway guard. |
| **Repeat detection in the ledger** | `tool_invocations.args_hash` | The idempotency key includes the call's position; a position-free hash finds repeats. The 2nd is served from the 1st's result with a note, the 3rd ends the run (R14.4). |
| **Ports & Adapters** (models) | [`models/provider.py`](../backend/src/agent_runtime/models/provider.py) `ModelProvider` → `ScriptedProvider`, `OpenAICompatibleProvider` | Agent files name a model *role*; the provider maps it to a model. OpenAI and Ollama share one adapter (Ollama speaks the OpenAI API). The scripted adapter keeps CI keyless; one contract suite runs the real adapter against a fake server, and against real Ollama on demand (`make test-live`). |
| **Observer** (live tokens) | [`streaming/tokens.py`](../backend/src/agent_runtime/streaming/tokens.py) `TokenRelay` | A callback handler on the graph sees every streamed token: it coalesces them into transient `token` events (never persisted), tracks the unfinished reply (persisted as `interrupted` if the turn is cancelled), and checks for a cancel twice a second so a long reply can be stopped mid-stream. |
| **Observer** (turn status, L2) | [`streaming/bus.py`](../backend/src/agent_runtime/streaming/bus.py) `publish_events` → `turn_status` | Every persisted run event carries its run's session (read in the same `UPDATE … RETURNING`), so the one post-commit publish path also tells the session's stream about the turn's lifecycle as a transient `turn.status`. No publish site had to change. |
| **Strategy** (demo responder, L2) | [`models/demo.py`](../backend/src/agent_runtime/models/demo.py) `RULES` | The offline model's reply to free text: an ordered rule table (calculator, note, search, helpers, approval, help), filtered by the agent's tools. Its script is stored in the run's input, so a replay reads it back rather than choosing again. |
| **Reducer / event sourcing** (UI, L2) | [`frontend/src/chat/transcript.ts`](../frontend/src/chat/transcript.ts) `chat` | The visible chat is a pure fold over events (replayed or live messages, tokens, turn status, helpers, the refetched session). Idempotent by `seq`; `lastSeq` is the contiguous high-water mark a reconnect resumes from: the client half of exactly-once display (AC20). |
| **State machine** (UI connection, L2) | [`frontend/src/stream/connection.ts`](../frontend/src/stream/connection.ts) | `idle → connecting → open ⇄ reconnecting → offline`, plus `drain`: pure, and shown as one plain banner. |
| **Adapter + functional core / imperative shell** (UI, L2) | [`frontend/src/stream/sessionStream.ts`](../frontend/src/stream/sessionStream.ts), [`chat/useChat.ts`](../frontend/src/chat/useChat.ts) | `EventSource` hides behind `openSessionStream`; the hook is the only place with effects (the stream, the 10 s safety-net refetch, helpers' results). Everything it feeds is pure and unit-tested. |
| **Defence in depth** (untrusted output, L2) | [`frontend/src/ui/Markdown.tsx`](../frontend/src/ui/Markdown.tsx), [`frontend/nginx/`](../frontend/nginx/) | Raw HTML skipped, the tree sanitised, links restricted, **images never loaded** (a prompt-injected image URL would exfiltrate data on render), tool data shown as text; a strict CSP behind all of it. |
| **Reverse proxy, one origin** (L2) | [`frontend/nginx/default.conf`](../frontend/nginx/default.conf) | nginx serves the UI and proxies `/api` to the API replicas: no CORS; SSE unbuffered; the upstream re-resolved every 2 s; no passive down-marking (it would leave no live upstream while one replica restarts and another dies); idempotent requests retried on the next replica. |
| **Pinned by hash** (L3a, R15.4) | [`agents/resolver.py`](../backend/src/agent_runtime/agents/resolver.py) `AgentResolver`, [`agents/store.py`](../backend/src/agent_runtime/agents/store.py) `snapshot_bundle` | A turn resolves its agent (built-in file, or a Studio version) when it is created, snapshots it as a content-addressed **bundle** (the agent and its helpers, in order) and stores the hash on the run. Workers build the agent from that snapshot, so publishing (AC47) or a deploy (rolling upgrade) never changes a running or queued turn. |
| **Specification** (one validator, L3a) | [`agents/loader.py`](../backend/src/agent_runtime/agents/loader.py) `validate_definition` | Files and the Studio feed the same `RawDefinition`s to one rule set (schema, catalog, ceilings, placeholders, helper rules); issues carry a section and a field, which the form shows in plain words. |
| **State machine in the database** (L3a, AC47) | migration 0010 trigger `agent_version_immutable` | draft → published → archived. A published version's content can't change and it can't be deleted: the trigger refuses it for every client, not just the API. "Tested" is derived (a completed test turn pinned to the draft's hash), never stored. |
| **Memoised factory / Flyweight** (L3a) | `AgentResolver.spec` | One compiled agent per bundle hash per process (an LRU), because a hash names an immutable definition. |
| **Debounced command** (L3a UI) | [`frontend/src/studio/StudioEditor.tsx`](../frontend/src/studio/StudioEditor.tsx) | Each edit goes through one handler: apply it (a pure reducer), mark it pending, save after a pause in typing. No effect watches the document, so nothing saves twice or races a server reply. |
| **Envelope encryption + Strategy** (keys, L3b, R18.3) | [`keys.py`](../backend/src/agent_runtime/keys.py) `seal` / `open_secret`, `KeyEncryptionKey` → `LocalKek` | Each saved key gets its own random data key (AES-256-GCM); the data key is wrapped by a key-encryption key. Locally the KEK is derived (HKDF) from `NURIA_SECRET_KEY`; the beta swaps in Key Vault behind the same port. `kek_version` records which master key wrapped each one, for rotation later. |
| **Bound to its place** (AEAD context, L3b, AC45) | `secret_aad(workspace, row, purpose)` | The ciphertext and the wrapped data key are authenticated with `workspace : row : purpose`, so a ciphertext copied to another connection, workspace or purpose fails to open: tested, not assumed. A keyed fingerprint (HMAC) tells keys apart without revealing them. |
| **Pinned by hash, continued: model bindings** (L3b, R15.4) | [`models/connections.py`](../backend/src/agent_runtime/models/connections.py) `ModelRouter.bind` → `runs.model_bindings` | When a turn is created, every model its bundle names (a role such as `chat`, or `<connection>:<model>`) is resolved to a connection and model and stored on the run. The worker uses those bindings, never the current default, so changing the default, or a crash and reclaim, can't switch a turn's model. |
| **Memoised factory** (providers, L3b) | `ModelRouter.providers` | One adapter per (connection id, `updated_at`, model): a key is opened in memory once per worker and process, and an edited connection (new key, new URL) gets a fresh adapter automatically. The circuit breaker is per connection, so one failing service doesn't stop the others. |
| **Fake server** (test double, L3b) | [`devtools/fake_model.py`](../backend/src/agent_runtime/devtools/fake_model.py), `runtime fake-model`, Compose profile `test` | A deterministic OpenAI-compatible service with a call log (which model, which key's hash). Routing (AC44), the capability test, key rotation and a worker crash on a user's connection are proven in CI with no real model or key. |
| **Untrusted text stays data** (L3c, R14.15) | [`untrusted.py`](../backend/src/agent_runtime/untrusted.py) `as_data`, ToolPipeline stage 12 | Every tool result (and so every skill a model loads) reaches the model inside `<data source=…>` delimiters it can't close (look-alike tags are escaped), and every prompt ends with the rule. Policy never depends on it: 22 planted-instruction cases assume a fully obedient model and check the harness still denies, asks or limits. |
| **Fail closed** (approvals, L3c) | ToolPipeline stage 6 | A gated tool runs only on an explicit `{"decision": "approve"}`. A rejection normally cancels the run first; the pipeline no longer relies on that. |
| **Specification + Chain of Responsibility** (skills, L3c) | [`skills/spec.py`](../backend/src/agent_runtime/skills/spec.py), [`skills/scan.py`](../backend/src/agent_runtime/skills/scan.py) | One function turns a form, an upload, an import or a built-in folder into an immutable `SkillContent` (the Agent Skills rules plus our limits), then a fixed chain of small checks (secrets, injection, links, encoded, invisible, code, size) produces one report: `block` refuses the save, `review` informs. |
| **Content-addressed, immutable by grants** (skill versions, L3c) | migration 0012 | A version's key is the hash of its content, files are keyed by sha256, and the API role can only insert and read them: the same skill is one row wherever it came from, and nothing written can change. |
| **Pinned by hash, continued: skills** (L3c, R15.4) | [`skills/binding.py`](../backend/src/agent_runtime/skills/binding.py) `bind`, `agent_versions.skill_lock` | The bundle a turn pins includes each owner's skill versions. Drafts follow the library (so "tested" is checked against today's skills); publishing freezes a `skill_lock` with the version (the AC47 trigger covers it), so editing a skill never changes a published agent. Hashes of agents without skills are unchanged. |
| **Progressive disclosure** (skills at run time, L3c) | `skills_section`, [`skills/tools.py`](../backend/src/agent_runtime/skills/tools.py) | The prompt lists names and "when to use"; `load_skill` / `read_skill_file` return the rest, through the full pipeline, granted only to whoever has skills and limited to the caller's own (`ToolContext.skills`). Scripts are never offered or readable. |
| **The answer is a tool call** (builder agents, L3c) | [`agents/builder.py`](../backend/src/agent_runtime/agents/builder.py), `backend/agents/agent-builder/`, `…/instructions-coach/` | "Describe it" and "Improve" are hidden agents whose one tool's arguments are the structured answer. The tool runs the one validator and returns the problems, so the agent's few turns are its repair rounds. They're ordinary runs (budgets, breaker, crash recovery); the result is a proposal, saved only when accepted. Offline, a keyword drafter (Strategy) writes the same shape. |
| **Derived progress** (Getting started, L3d) | [`onboarding.py`](../backend/src/agent_runtime/onboarding.py) | Each step is a Specification over facts already in the account (a ready default model, the guide's agent with a tool and a helper, a completed test, a published version, a real chat). ## Spike: fencing LangGraph checkpoints (phase 1, task 1.4)

**Question:** can we stop a zombie worker's checkpoint writes without forking LangGraph?

**Approach:** wrap each checkpoint write in our own transaction. `SELECT epoch FROM runs … FOR NO KEY UPDATE` runs first; if the epoch isn't ours, raise `FencedError` and roll back. Otherwise LangGraph writes on that same connection. The row lock conflicts with the takeover's `UPDATE … epoch = epoch + 1`, so the check and the write are atomic with respect to a takeover. (Phases 1–5a used `FOR SHARE`. Phase 5b changed it: two concurrent transactions of one run, such as parallel tool calls or sub-agents' checkpoints, each upgrading a share lock, deadlocked.)

**Results** (3-node graph; node `b` triggers a takeover mid-run):

| Scenario | Zombie behaviour | Persisted |
|---|---|---|
| No fence (plain LangGraph) | Executed `b` and `c` and finished | `[a, b, c]`: the zombie's work won |
| Fence, `durability="sync"` | Stopped right after `b` | `[a]`: the new owner resumes from here; `a` is not re-run |
| Fence, `durability="async"` (LangGraph default) | Stopped, but only **after executing `c`** | nothing: even `a` was lost |

**Conclusions**
1. **Fencing works on the public API.** Only `aput`, `aput_writes` and `adelete_thread` write; the other write hooks aren't implemented by the Postgres saver.
2. **`durability="sync"` is mandatory** for every run. With async durability a zombie executes extra steps (extra side effects) before learning it's fenced, and more progress is lost.
3. **Fencing bounds what a zombie can *persist*, not what it can *do*:** `b` executed twice. External side effects therefore also need idempotency keys (R2.6, phase 4).
4. **Cost:** one extra round trip (`SELECT … FOR NO KEY UPDATE`) per checkpoint write, plus a short row lock held until that write commits. A run's fenced writers serialise on it, as they already did at the event sequence.
5. **Ownership:** LangGraph creates and migrates its own tables (`checkpoints`, `checkpoint_blobs`, `checkpoint_writes`, `checkpoint_migrations`) through `setup()`; Alembic manages ours. The migrate step will run both (phase 1, task 1.7).

Tests: [`test_fenced_checkpointer.py`](../backend/tests/integration/test_fenced_checkpointer.py), including a control test proving that the unfenced zombie really does corrupt the run.

## Sub-runs vs. LangGraph `Send` (R2.8 design decision)

`Send` fans out inside one superstep on one worker; it can't cross a process boundary. Modelling each researcher as a **child run** is what lets the fan-out spread across pods, and it gives every child its own checkpoint, lease and reclaim for free. The cost is a parent/child protocol: spawn in one fenced transaction, an atomic fan-in counter, re-enqueue, partial results, a cancel cascade and budget roll-up. Sub-agents (CR-005) are the third option: in-process delegation with live status, bounded by one worker. See [ADR-0005](adr/0005-fan-out-child-runs.md).
